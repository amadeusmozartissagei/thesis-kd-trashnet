Editing/QA'ing PowerPoint decks on this machine (learned 2026-07-01, sempro deck in `outputs/`):

- **Store Python sandbox:** the default `python` is `C:\Users\...\WindowsApps\python.exe` (Store 3.11). It **cannot open files under `...\AppData\Roaming\Claude\...skills...`** (Errno 2 even when the path exists) — so the pptx skill's `unpack.py`/`pack.py`/`soffice.py` scripts fail. It CAN read/write the user's `Documents`/`outputs` folders fine. `python-pptx` and LibreOffice were NOT preinstalled.
- **Unpack/repack manually:** a .pptx is a zip → `Copy-Item deck.pptx deck.zip; Expand-Archive` to unpack; repack with Python `zipfile` (walk dir, arcnames with forward slashes, write `[Content_Types].xml` first, `ZIP_DEFLATED`). PowerPoint accepts this (no mimetype-order requirement, that's ODF). Edit slide XML directly with Edit/Write; validate well-formedness with `xml.dom.minidom`.
- **Adding a slide** needs 4 registrations: `[Content_Types].xml` Override, `ppt/_rels/presentation.xml.rels` Relationship (new rId), `ppt/presentation.xml` `<p:sldId>`, and `ppt/slides/_rels/slideN.xml.rels` (→ slideLayout1). Reuse an existing content slide's geometry for safety.
- **Render QA toolchain (now INSTALLED via winget):** `TheDocumentFoundation.LibreOffice` (soffice at `C:\Program Files\LibreOffice\program\soffice.exe`) + `oschwartz10612.Poppler` (pdftoppm at `...\WinGet\Packages\oschwartz10612.Poppler_*\poppler-*\Library\bin\pdftoppm.exe`). Convert: `soffice --headless -env:UserInstallation=file:///C:/Users/Pratama/AppData/Local/Temp/lo_profile --convert-to pdf --outdir <dir> deck.pptx`, then `pdftoppm -jpeg -r 110 deck.pdf slide`. The Read tool can view the JPGs (it needs pdftoppm to read PDFs directly, so rasterize first). soffice prints a harmless "Could not find platform independent libraries" warning — ignore it.
